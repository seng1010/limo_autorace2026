# M8 출구 준비와 제어권 인계 분리

기준: `26c63ea`, `feature/m8-cone-corridor`. 2026-11-16.

## 왜 수정했는가

기존 `handoff_on_detection=True`는 출구선이 확정되면 즉시 차선 쪽에 제어권을 준다. 이때 차선 연결 원호가 마지막 콘에 막히면 정상 콘 제안이 있어도 0 명령을 내보낸다. `020242` 기록 약 43초 이후가 이 경우다. 충돌검사와 마진을 낮출 문제가 아니라, 아직 사용할 수 있는 콘 명령을 출구 준비만으로 차단한 인계 문제다.

## 새 정책

`(서로 다른 출구선 확인 OR 관측 콘·odom 통과 확인) AND 신선하고 LiDAR 검사를 통과한 차선 명령`

- `cone`: 기존 콘 제어. 기본 차선 노드는 계속 관측한다.
- `exit_prepare`: 출구 증거를 확보하면 차선의 30cm 검사/40cm 연결 원호를 병행 계산한다. 사용할 차선 명령이 없으면 **기존 콘 명령**을 유지한다. 콘 명령까지 유효하지 않으면 기존 정지/제한 전진 복구 규칙을 따른다.
- `exit_lane`: 안전한 차선 명령을 실제 받은 시점에 한 번 인계한다. 이후 콘 명령이 차선을 다시 덮어쓰지 않는다. 차선 명령 만료/실패는 정지한다.
- 다음 미션은 출구선 통과 또는 신선한 콘 통과 증거와, 기존 차선 인계 후 odom 15cm 진행 조건을 함께 확인한다. 정지선 검출 범위·3회 확인·간격·통과 마진은 그대로다.
- 출구 준비/인계 중에는 콘 계획기의 목표 기억, 기존 진입 보조 탐색의 사용 시간·거리, 이미 계산한 차선 형상과 차선 연속 확인 횟수를 불필요하게 초기화하지 않는다. 다른 미션 전환과 수동 후진/odom 이상에 대한 기존 계획기 초기화는 유지한다.

## 누적 콘 위치의 의미와 한계

`ConeExitMemory`는 계획기가 실제 관측해서 선택한 통로 양 끝의 콘 클러스터를 odom 좌표에 저장한다. 예측 목표로 기록을 갱신하지 않는다. 같은 쌍의 독립 스캔 2회 확인 후 사용하며, 최대 16쌍으로 계산량을 제한한다.

관측된 콘 점들의 진행 방향 최대 돌출 위치와 **차체 직사각형 네 모서리 전체**를 비교한다. 받침 1.5cm와 추가 여유 2cm를 그대로 포함한다. 차량 중심만 통과하거나 콘이 가려지는 것은 통과가 아니다. 전방에 다음 콘 후보가 남거나 진행 방향의 40cm 관측이 불충분해도 콘 통과 증거를 주지 않는다.

odom 유실·점프·후진·시간 불연속은 기록을 초기화한다. 아직 통과하지 않은 기록의 관측이 12초를 넘거나 저장 상한에 닿으면 `unknown`에 해당하는 false를 유지한다. 기록 삭제/만료를 탈출로 해석하지 않는다. 이미 통과한 쌍도 좌표를 유지하며 새로운 차체 위치로 다시 확인한다. 이는 전체 공간의 완전한 지도/SLAM이나 가려진 모든 콘이 없다는 보장이 아니다.

이 기록은 **출구 문맥만 제공**한다. 실제 이동 명령은 기존 원시 LiDAR 충돌검사를 거친 차선/콘 명령에서만 나온다.

## 변경하지 않은 것

- 속도 0.10m/s, 음수 속도 거부, 자동 후진 없음
- 받침 보정 0.015m, 추가 여유 0.020m, 차체 크기·최대 곡률
- `cone_corridor.py` 전체: 콘 20cm, 일반 출구 차선 30cm, 대체 차선 연결 40cm 검사 및 원호 점수
- 250ms 명령 만료, 실제 odom을 사용하는 제한 전진 복구의 거리·시간·재시도 예산
- 기존 race 차선 알고리즘, 공용 매니저, 하드웨어/조향 bridge, 진입 조건

## 두 bag의 비교

자료: `bag_m8_local_20261116_020142`, `bag_m8_local_20261116_020242`.
외부 검증 도구: 작업 폴더의 `m8_offline/verify_exit_handoff.py`, `render_exit_handoff.py`.

1. 같은 scan/odom 위치에 동일 계획기와 출구 차선 검사를 재실행했다. 출구 단계 이전의 콘 상태·속도·곡률·최소 여유가 수정 전과 동일한지 assert했다. 후보 차선 경로도 기존 충돌검사를 통과하는지 확인했다.
2. 수정 전/후 **실제 M8Control 클래스**를 ROS 메시지 모형으로 실행하고, 기록된 콘/검증 차선/복구 명령 수신 시각과 odom에 넣었다. 제어 타이머는 50ms로 샘플링했다. 초반 M8 인계 시점과 기록된 출구선 관측은 유지했다. bag 수신 시각은 실제 DDS 도착 시각의 근사다.

## 검증 범위와 실차 확인

영상의 카메라와 odom은 원본이다. 새 명령으로 차량을 움직인 폐루프 재현이 아니며, 명령 전달 시간 개선을 완주율/충돌 확률로 환산하지 않는다. 이번 두 bag에서 콘 통과 단독 증거는 성립하지 않았다. 이 분기는 합성 좌표 이동·회전·후미 통과·가림·만료·후진/odom 이상 테스트로 검증했고, 실차 양성 확인이 필요하다.

실차에서는 다음을 확인한다.

1. 출구선이 보여도 `exit_prepare`에서 검증 콘 명령이 이어지는가.
2. 안전한 차선 명령이 도착하면 `exit_lane`으로 바뀌고 조향이 그 명령과 일치하는가.
3. 출구선 없이 실제 마지막 관측 통로를 차체 뒤까지 통과한 경우 `exit_progress.x=1`이 발생하는가. 가림/정지/후진만으로는 발생하면 안 된다.
4. 인계 후 차선 유실/센서 만료/ESTOP는 기존과 같이 정지하는가.
5. 기본 차선·진입·콘 내부 속도/마진이 바뀌지 않았는가.

`m8_cone.launch.py`의 bag 목록에 `/mission/cone/exit_progress`를 추가했다. `PointStamped`의 stamp는 스캔 획득 시각, frame은 `rear_axle`, x는 통과 확인(1/0), y는 확인된 통로 쌍 수, z는 전체 차체 통과 여유(m; 미확인 시 0)다. `/mission/cone/timing`의 `exit_progress.reason`으로 가림/기록 만료/후미 미통과를 구별한다. 이 토픽은 명령이 아니다.
