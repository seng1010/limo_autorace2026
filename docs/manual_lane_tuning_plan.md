# 수동 디버거 튜닝 및 후속 리팩토링 계획

기준: `fix-lane-near-gates`, 기존 근거리 목표 검사 및 선택적 우곡선 진입 정책 보존.
첨부 분석의 기준 `ef8a6ed`와 현재 코드는 다르므로 과거 줄 번호를 수정 근거로 그대로 사용하지 않는다.

## 이번 변경

1. **튜닝 계약**: 색상·조명, 윈도우·피팅, 목표거리·곡선, 계산 속도·조향의 허용 목록과 범위를 정의한다. 유한 숫자/자료형/상호 조건을 검증한다.
2. **GUI 적용**: 그룹별 JSON 편집 → Apply → 노드 검증 → 후보 파이프라인 생성 → ROS 파라미터 일괄 설정 → 파이프라인 교체와 이력 초기화. 잘못된 요청은 전체 거부한다. 새 검출기가 아니라 실행 중인 파이프라인을 바꾼다.
3. **독립 비교**: `right_curve_floor_enabled`, `curve_preview_enabled`를 각각 끌 수 있다. 기존 동작 보존을 위해 둘 다 기본 true. 둘 다 false이면 해당 두 보정 없이 Pure Pursuit 목표가 변화율 제한기로 전달된다. 근거리 전용 경로 생성까지 제거하는 스위치는 아니다.

## 사용

카메라가 실행된 상태에서 NoMachine 데스크톱 터미널:

```bash
source ~/2026_ws/install/setup.bash
ros2 launch jetracer_ros2 lane_debug.launch.py outer_curve_entry:=true
```

- Parameters에서 그룹 선택 → 숫자/true/false 수정 → Apply.
- 적용값 불러오기는 편집 중인 값을 현재 적용값으로 되돌린다.
- 적용 후 추적/조향/서행 이력을 초기화하므로 몇 프레임은 안정화 시간이 필요하다.
- Copy all applied parameters는 적용된 값만 클립보드로 복사한다. JSON은 YAML로도 읽을 수 있다. 자동 저장/재시작 유지 기능은 없다.
- `all_in_node.launch.py`의 자동주행 디버그 창에서는 편집이 잠긴다. 수동 디버거도 다른 teleop가 차량을 움직이는 것을 차단하지 않으므로 설정 변경은 물리적으로 정지한 상태에서 한다.
- 튜닝 목록의 값은 실행 중 `ros2 param set`으로 부분 변경하지 못하게 했다. GUI Apply 또는 시작 시 파라미터 파일을 사용한다. `timing_log_enabled`는 기존대로 실행 중 변경 가능하다.

## 의도적으로 잠근 항목

- ROI/BEV 네 점, 지면 좌표, 카메라 오프셋, 휠베이스·트레드: 물리 측정과 이미지 보정 기준을 함께 확인해야 한다. ROI만 바꾸면 metric 보정이 틀어질 수 있다.
- publish_commands, 타임아웃, 복구 거리·시간 및 odom 복구 활성화: GUI가 차량 제어 권한이나 안전한계를 변경하지 않는다.
- steering_gain 등 실제 Pure Pursuit 경로에서 사용되지 않는 과거 게인: 편집해도 효과가 없는 항목을 노출하지 않는다. 소스 삭제는 이후 별도 회귀 검증 단계다.
- `metric_ackermann=false`: 레거시 자동주행 비교 모드가 아니다. 지면 목표가 없어 자동주행은 정지하며 인식 화면 비교만 가능하다.

## 다음 단계와 필요한 자료

| 순서 | 작업 | 진입 조건 / 검증 |
|---|---|---|
| 4 | 동일 영상의 기본/최소우조향 OFF/Preview OFF/둘 다 OFF 비교 | 최신 원본 카메라 + CameraInfo + 명령 rosbag. 첫 조향 시점, 반대방향 복귀 명령, 포화 시간 비교 |
| 5 | 미사용 함수·파라미터 삭제 | 실제 제어 경로의 명령 회귀 테스트 확보 후 동일 출력 확인 |
| 6 | 공통 지면 경로와 signed curvature | BEV 점이 왜곡 보정 전/후 어느 영상 기준인지 확인, 지면 실측 검증 |
| 7 | 곡선 상태·재탐색 분리, 동적 Lookahead | 현재 관측 범위 안의 목표만 허용. 잠금 해제와 주행 허가는 독립 검증 |
| 8 | 단일 차선 법선 경로와 odom 기반 추정 | 경로 접힘·경계 침범 검증, odom/IMU 시간·단위·방향 검증 후에만 복구 활성화 |

사용자는 보정 전/후 기준을 모른다고 답했다. 리모 저장소는 드라이버 설정 확인에는 도움이 되지만 당시 실측 영상의 기준이나 실차 rosbag 존재를 증명하지 못한다. 해당 차량 저장소 경로/커밋과 원본 로그가 필요하다. 이번에 외부 프로젝트 알고리즘을 복사하거나 실차 성능 향상을 확정하지 않았다.

## 실차 체크리스트

- [ ] 수동 디버거에서 설정 편집·거부 메시지·적용값 복사가 보인다.
- [ ] 색상 임계값/윈도우 수를 바꾸면 화면에 반영된다.
- [ ] 잘못된 값과 NaN을 넣어도 기존 설정이 유지된다.
- [ ] 카메라가 멈춰도 편집 응답이 도착한다.
- [ ] 자동주행 디버그 창에서는 Apply가 잠긴다.
- [ ] 수동 디버거가 inference/cmd_vel 또는 /cmd_vel 발행자를 추가하지 않는다.
- [ ] 재시작하면 저장하지 않은 튜닝 값은 초기 설정으로 돌아간다.
- [ ] 낮은 속도·비상정지 준비 하에 동일 구간 A/B 비교한다.

로컬에서는 순수 계산과 ROS 대역 테스트를 수행한다. 실제 ROS2 그래프, NoMachine/Tk 창 배치, Jetson 성능과 주행은 별도 실차 검증 대상이다.
