# 차선주행 전체 분석 반영 현황

기준: `fix-lane-near-gates` (2026-11-14). 첨부 분석은 과거 `ef8a6edd`를 기준으로 작성되었으므로, 아래 판단은 현재 브랜치의 실제 호출 경로를 다시 확인한 결과다. 원문은 수정하지 않는다.

## 변경 충돌과 안전 기준

- 곡선 완주를 위해 무관측 상태에서 무기한 우조향하는 안은 폐기한다. 관측 경로·시간·이동량 상한과 안전 정지를 유지한다.
- 빠른 코너 진입을 위한 가까운 목표와 직선 안정화를 위한 먼 목표는 **동일한 지면 경로**에서 선택해야 한다. 0.40 m 요청을 관측되지 않는 지점으로 외삽하지 않는다.
- 노란 우곡선 우선 탐색은 흰 매트 테두리 오검출 방지에 필요하지만, 래치 해제를 곧바로 주행 허가로 연결해서는 안 된다.
- `confidence`는 관측 품질 점수이지 곡선 완주 확률이 아니다. 낮은 점수를 임의로 통과시키는 대신 관측·경로·정책 게이트의 실패 이유를 분리한다.
- `/cmd_vel`은 미션 매니저 단독 발행, 카메라 노드는 후보 명령만 발행하는 구조를 유지한다.

## 남은 구현 순서와 실차 자료

1. 동일 원본 카메라/CameraInfo 및 명령 기록으로 현재/우조향 floor OFF/Preview OFF/둘 다 OFF를 비교한다. 화면녹화는 육안 확인에는 유용하지만 원본 이미지 좌표와 명령 시각 회귀 기준은 아니다.
2. BEV 네 점이 원본 영상인지 왜곡 보정 후 영상인지 확인하고, 실측 거리·카메라 설치 자세·실제 목표거리 분포를 기록한다. 확인 전에는 수치 보정과 동적 Lookahead 기본 활성화를 하지 않는다.
3. 검증된 지면 경로로 진입·유지·탈출의 국소 곡률과 접선 방향을 판단하고, 곡선 래치 해제/재탐색/주행 허가를 별도 상태로 분리한다. 직선·우곡선·출구·S자·한쪽 선 유실 회귀 사례가 필요하다.
4. 같은 지면 경로에서 동적 Lookahead와 단일 차선 법선 복원을 비교한다. 경로 접힘, 관측 범위 밖 목표, 차체 폭/경계 침범은 즉시 거부한다.
5. 실차 `/odom`의 frame, 시간, 위치·yaw 부호, 정지 중 드리프트 및 이동거리 재현성을 확인한다. 현재 odom 복구는 켜져 있지만 실차 검증 완료로 표기하지 않는다. 확인 후 KF/EKF와 장거리 예측 여부를 판단한다.
6. Jetson 실제 p50/p95 입력 나이·처리시간을 측정한 뒤 프레임 큐, 왜곡 보정 맵 캐시, 노란선 중복 탐색, 디버그 JPEG 순으로 최적화한다. Stanley/PID는 동일 지면 경로가 안정화된 후에만 A/B 후보로 둔다.

실차 검증 자료: 원본 카메라·CameraInfo·`/odom`·`/imu`·`/lane/model`·`inference/cmd_vel`·`/cmd_vel`의 같은 시간대 기록, 직선/우곡선 진입·중간·출구 및 서행 영상. 현재 사용자가 제공한 것은 화면녹화와 카메라 자료이며 odom 기록은 없다. 위 계획은 코드 구현 상태와 실차 검증 상태를 섞어 표기하지 않는다.
