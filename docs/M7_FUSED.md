# M7 차로·장애물 융합 주행

`simple_lane drive lane3 l3mapped`에만 적용되는 M7 구현입니다. 일반 `simple_lane`, `l3simple`, 다른 미션 노드는 기존 구현을 유지합니다. 기준 버전은 `m7-measurement-20261117`이며, 비교 기준 코드는 `4d1dd37`입니다.

## 구현 구성

1. **차로·시각 정합** — 흰 점선과 노란 실선을 공동 배치해 좌·중·우 차로 가설을 계산합니다. 처리 프레임 수 대신 실제 시간으로 보정합니다. 큰 위치 수정은 정지 후 일관된 관측으로 확인합니다. 새 점유가 반복 관측되어도 정지 확인 시간을 매번 초기화하지 않습니다. 한 경계는 기존 위치 유지에만 쓰고 차로를 새로 확정하지 않습니다. 입력 나이는 센서 header와 수신 시간을 모두 검사하며, odom 보간 실패 시 최신 값으로 대체하지 않습니다.
2. **도로·점유·빈 공간** — 시작 시 도로 원점·방향과 3차로를 고정한 맵 좌표에 장애물을 보존합니다. odom 이동으로 차량 위치를 갱신하고 카메라 차선으로 차량의 map←odom 변환을 보정합니다. 카메라 보정 때 도로·기존 장애물 위치를 함께 흔들지 않습니다. 이는 사전 실측 지도나 SLAM의 전역 위치 보장이 아니며, 초기 진입 위치와 종방향 odom 오차는 남습니다. 2cm 격자는 저장 인덱스로 사용하고 충돌 검사는 셀 안에 실제로 측정된 점의 범위로 수행합니다. 가려진 점유는 유지하며 0/NaN은 빈 공간이 아닙니다. 표면 간 최소 거리가 0.50m 이내면 같은 그룹으로 표시하며, ID, 진행 방향 근거리/원거리, 겹치는 차로를 기록합니다. 묶인 그룹의 사각형을 통째로 막지 않아 내부의 통과 가능한 틈은 보존합니다. ID 수를 실제 자동차 수로 해석하지 않습니다.
3. **경로 탐색·추종** — 축간거리·윤거·최대 조향각으로 아커만 운동을 적분해 처음부터 실행 가능한 차로 변경 곡선을 만들고, 없으면 같은 모델의 조향 동작을 연결하는 제한된 Hybrid A* 탐색을 합니다. 모델 곡선의 조향 프로파일도 저장하며, 작은 선행 조향 항과 실제 위치·방향 오차 보정을 결합해 추종합니다. 탐색 비용은 이동 거리와 조향 변화량을 포함하지만, 시간 제한이 있으므로 전역 최단거리 보장은 아닙니다. `planner=lattice`는 정확한 격자 끝점과 곡률 제한을 만족하는 quintic 동작들을 사용하는 비교 구현입니다. 두 구현은 같은 차체/도로/점유 검사를 사용합니다. **Nav2 Smac을 호출하거나 그대로 이식한 구현은 아닙니다.** ROS 없는 환경에서도 동일 핵심 코드를 검증하기 위한 독립 구현입니다.
4. **정지·재계획·후진** — 새 점유 발견 또는 실행 경로 차단 → 정지 명령 → odom 정지와 새 scan 확인 → 경로/실제 조향 명령 확인 → 출발 순서입니다. 후진은 실제 지나온 자세 이력과 좌·우 최대 조향/직선 후진 후보를 검사합니다. 5→10→15→25→40→60cm 순서로, 후진 후 전진 곡선이 열리는 가장 짧은 후보를 선택합니다. 오른쪽 전방이 열리려면 뒤쪽을 왼쪽으로 보내 앞부분을 오른쪽으로 돌리는 방향을 사용합니다. 원래 지나온 이력과 맵의 빈 공간 증거(최대 20초), 최신 점유를 함께 검사하며 미관측 후방은 허용하지 않습니다. M7의 정적 장애물 가정입니다. 후진 중 0.1초 간격으로 전진 가능 여부를 다시 검사하고 각도가 확보되면 종료합니다. 같은 막힘에서 최대 3회이며 0.5m 이상 전진해 다음 구간에 도달하면 횟수를 회복합니다. 미션 전체 후진을 3회로 제한하지 않습니다.
5. **연산 분리·선택적 depth** — 센서 콜백은 최신 입력만 교체합니다. 별도 작업 스레드가 영상/지도/경로를 계산하고, ROS 실행 흐름의 20Hz 정지 검사는 계산 결과의 유효 기간과 새 scan의 제동 경로 충돌을 독립 검사합니다. JPEG/JSON 쓰기는 크기가 제한된 별도 대기열을 사용합니다. Depth는 보정값이 확인된 경우에만 추가 점유 층으로 결합합니다.

경로는 고정 맵 좌표에 저장해 재사용합니다. 새 장애물, 경로 이탈/차단, 목표 변경, 경로 끝 접근 시 재탐색합니다. 지도와 경로 검사, 정지 판단은 계속 수행합니다. 탐색이 늦거나 입력이 오래되면 정지합니다. 작업 스레드는 Python GIL과 운영체제 스케줄러를 공유하므로 하드 실시간 보장은 아니며, 계측으로 실행 지연을 확인해야 합니다.

## 기본 설정과 아직 확인할 항목

설정 파일은 `src/jetracer_ros2/params/m7_fused.json`이며 설치 시 패키지 share/params에 복사됩니다.

- `entry_s=0.30`: **카메라 지면 투영점이 M7 시작선에서 0.30m 전방인 위치**를 진입 기준으로 가정합니다. 현재 배치에 맞게 설정해야 합니다. 가려진 뒤 처음 보인 점선을 첫 번째 점선으로 간주해 종방향 위치를 자동 확정하지 않습니다. 주행 도중 이동시켰다면 이 기준과 odom 지도의 일치도 다시 확인해야 합니다.
- `lidar_x/y/yaw`: odom에 사용하는 후륜축 지면 기준점에서 라이다까지의 변환입니다. 기본 x=0.184m는 기존 코드 값을 유지했습니다. 공식 제품의 다른 base_link 변환을 그대로 섞으면 안 됩니다.
- `raytrace_min_range=0.02`: T-mini Pro 제품 사양의 물리적 근거리 한계입니다. LaserScan의 `range_min`은 유효한 반환값을 거르는 데 별도로 사용합니다. 유효 반환 광선은 물리적 근거리 한계부터 끝점 전까지 빈 공간 증거로 사용합니다. 설치 센서/필터의 실제 의미가 다르면 이 설정도 변경해야 합니다.
- 인접한 유효 광선의 각도 간격이 1.5° 이하이고 거리 차가 12cm 미만이면, 가까운 끝점까지만 두 광선 사이 격자 틈을 채웁니다. **무효 광선 사이, 큰 거리 불연속, 장애물 뒤는 연결하지 않습니다.** 자동차 장애물이 단일 광선 간격보다 크다는 가정을 사용합니다. 가는 막대 검출을 보장하는 모델은 아닙니다.
- `speed=0.40`: 최대치입니다. 곡률·최대 조향까지 남은 여유·관측된 제동 거리·실측 odom 속도에 맞춰 낮추며 가속도는 0.25m/s²로 제한합니다. 표지판 읽기는 기존 0.08m/s로 제한합니다. 조향각 모델 최대치는 ±24°입니다.
- 바깥 차선과 교통섬은 차체 전체의 금지 경계입니다. 모서리와 변을 검사하며, 양끝 차선을 넘는 후보는 점수와 무관하게 제외합니다.
- `margin=0.035`: 센서·추종 여유는 유지합니다. 저장 셀 중심으로 인한 과도한 추가 확장을 실제 관측 범위로 바꿨으며 총 여유를 임의로 1~2cm로 줄인 것은 아닙니다.
- `deskew=false`: 광선별 움직임 보정 구현은 있으나 현재 실제 드라이버의 자르기/각도 배열/첫 광선 시각 정의가 확인되지 않았습니다. 이를 확인한 뒤 `scan_timing_verified=true`와 함께 켭니다. 광선별 odom이 없거나 시간 범위가 맞지 않으면 정지합니다.
- 조향 응답·제동 감속도는 기존 모델을 바탕으로 합니다. 실제 구동 응답과 장착 변환, RGB의 BEV 보정은 실차 확인 대상입니다.

내부 차로는 `0/1/2 = 좌/중/우`, 진단의 `lane_number`, `lane_numbers`는 사람이 읽는 `1/2/3 = 좌/중/우`입니다. 장애물이 두 차로에 걸치면 둘 다 표시합니다.

## 실행

하드웨어 드라이버와 bridge는 기존 teleop 실행 구성을 사용합니다. 다음은 워크스페이스에 최신 코드가 준비된 이후의 예입니다.

```bash
source /opt/ros/humble/setup.bash
source ~/wego_ws/install/setup.bash
cd ~/race_ws
colcon build --symlink-install --packages-select jetracer_ros2
```

빌드 성공을 확인한 다음 새 터미널에서 실행합니다.

```bash
source /opt/ros/humble/setup.bash
source ~/wego_ws/install/setup.bash
source ~/race_ws/install/setup.bash
export ROS_DOMAIN_ID=2
export OPENBLAS_NUM_THREADS=1
export OMP_NUM_THREADS=1
ros2 run jetracer_ros2 simple_lane drive lane3 l3mapped rec --headless
```

`--headless`를 빼면 M7 영상과 상태를 표시합니다. 현재 M7 화면은 상태 확인용이며 기존 일반 주행 튜너 전체 레이아웃과 다릅니다. `drive`를 빼거나 `view`로 바꾸면 **주행 명령을 발행하지 않습니다.**

A/B 표지판 판정에는 **이 버전의 `yolo_detection_node`**와 학습된 모델이 필요합니다. 기존 launch가 검출기를 실행 중이면 중복 실행하지 않습니다. 모델 경로는 차량에서 실제 사용 중인 경로를 지정합니다. 모델 없이 빈 detections만 나오는 상태에서는 갈림길을 임의 선택하지 않고 기다립니다.

촬영 시각으로 odom을 보간하며, 카메라의 횡위치 ±0.25m·방향 ±12°·신뢰 가능한 두 차선 관측을 요구합니다. 검출 신뢰도 ≥0.65, 480px 높이 기준 bbox 높이 ≥33px, 0.8초 내 최근 5장 중 4장(0.2초 이상에 걸친 독립 영상)을 확인합니다. 영상이 0.35초 넘게 오래되면 투표하지 않습니다. 표지판 확정 전 차체 앞부분이 교통섬 앞 0.95m 경계를 넘지 않도록 접근 경로를 끝냅니다. 중앙에서 정렬된 채 도달하면 `WAIT_SIGN`이며, 표지판만 없다는 이유로 후진하지 않습니다. 이것은 실제 표지판 크기/각도에서 검증할 기준값이지 오검출 방지 보장은 아닙니다.

설정을 별도로 수정하려면 사용자 경로에 JSON을 복사한 뒤 지정합니다.

```bash
ros2 run jetracer_ros2 simple_lane drive lane3 l3mapped rec --headless --m7-config ~/m7_fused.json
```

독립 실험에서는 `/cmd_vel`을 직접 발행합니다. 미션 매니저와 연결하는 구성은 `--topic inference/cmd_vel`을 사용하고, 기존 lane 추종기와 같은 출력 토픽을 중복 발행하지 않아야 합니다. 다른 미션의 시작/전환 구성은 변경하지 않습니다.

### 정지 유지와 재개

```bash
ros2 topic pub --once mission/obstacle_avoid/recovery std_msgs/msg/String "{data: hold}"
ros2 topic pub --once mission/obstacle_avoid/recovery std_msgs/msg/String "{data: resume}"
```

`resume`는 강제 전진이 아닙니다. 정지 확인·신선한 관측·통과 가능한 제동 경로가 있어야 다시 움직입니다. 지도 초기화 기능으로 사용하지 않습니다.

### 기록

`rec` 기록은 `~/simple_lane_log/MMDD_HHMMSS_drive_m7/` 또는 `..._view_m7/`에 저장합니다.

| 파일 | 내용 |
|---|---|
| `run_start.json`, `tune_start.json` | 실제 설정, 버전, 실행 모드, 출력 토픽 |
| `m7.jsonl` | 핵심 제어기가 제안한 명령, 차로·지도·경로·복구 상태 |
| `m7_commands.jsonl` | 독립 정지 검사 뒤의 `published_v`, 지연, CPU, gate_reason. 보기 모드는 published_v=null |
| `m7_scans.jsonl` | 원래 라이다 값, 취득 시각, time_increment/scan_time |
| `00001.jpg` 등 | 실제로 처리한 영상. 원래 카메라의 모든 프레임은 아님 |

`published_v`도 실제 차량 속도가 아닙니다. 실제 이동은 odom으로 판단합니다. 기록 대기열이 차면 제어를 막는 대신 일부 기록을 버리고 `record_dropped`를 증가시킵니다. 디스크 오류도 진단에 남깁니다.

Bag에는 다음을 함께 담을 수 있습니다. 이 명령은 녹화만 합니다.

```bash
ros2 bag record -o ~/bag_m7_fused_$(date +%Y%m%d_%H%M%S) \
  /camera/color/image_raw/compressed /camera/color/camera_info \
  /scan /odom /limo/odom /limo/ack_cmd /cmd_vel \
  /simple_lane/debug/m7 /mission/obstacle_avoid/recovery \
  /mission/active /perception/detections /tf /tf_static
```

CPU 전체 사용률은 진단의 `host_cpu_percent`, 이 프로세스의 전체 CPU 대비 비율은 `process_cpu_host_percent`, 한 코어를 100%로 세는 값은 `process_cpu_core_percent`입니다. GPU·온도·전력 모드는 별도 `tegrastats` 기록으로 함께 확인합니다. 평균 CPU만으로 성공 여부를 판단하지 않고 `control_interval_ms`, 센서 나이, `total_ms`의 95/99백분위와 정지 사유를 봅니다.

## Depth 켜기

기본값은 꺼짐입니다. 기존 수동 bag에는 depth가 없어 실제 효과를 검증하지 못했습니다.

활성화하려면 실제 depth 토픽/CameraInfo/frame_id, 깊이 단위, 카메라 광학 좌표에서 **후륜축 지면 기준 좌표**로의 4×4 `T_base_optical`을 확인해야 합니다. 광학 좌표의 x=오른쪽, y=아래, z=전방을 차량 좌표 x=전방, y=왼쪽, z=위로 변환합니다. RGB CameraInfo를 depth에 재사용하지 않습니다.

이 값들을 설정한 뒤 `depth.calibration_verified=true`, `depth.enabled=true`로 켭니다. 기본 16UC1은 mm→m의 0.001, 32FC1은 m 단위의 1.0을 가정하므로 실제 드라이버 단위와 다르면 scale 항목을 바꿉니다. 미보정 상태에서는 시작 시 오류로 거부합니다.

Depth는 관심 높이의 점을 추가하는 **점유 전용 층**입니다. 라이다가 낮은 높이로 지나갔다고 위쪽 돌출부를 지우지 않습니다. 반대로 depth 무효값을 빈 공간으로 바꾸지도 않습니다. 노이즈로 생긴 depth 점유의 적극적인 삭제는 현재 하지 않으므로, 잘못된 보정·반사점은 정체를 일으킬 수 있습니다. 실제 depth 자료로 검증한 뒤 사용해야 합니다. 활성화 시 해당 두 depth 토픽도 bag 목록에 추가합니다.

## 장비 없이 검증

ROS 없이 numpy, OpenCV, pytest로 실행합니다. bag 재생에는 추가로 rosbags가 필요합니다.


### 실제 수동 bag에서 남은 문제

`bag_m7_manual_20261116_031659`를 같은 작업 루프로 재생했습니다. 제어 773회, 처리 영상 365장, 경로 탐색 10회이며 입력 해석 예외는 없었습니다. 이전 녹화의 `tune_start.json`을 사용했습니다. 수동 차량 궤적은 새 제어기의 정지 요청과 무관하게 계속 움직입니다.
