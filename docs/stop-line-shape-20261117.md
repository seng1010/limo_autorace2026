# 마름모 정지선 오검출 차단과 어두운·비스듬한 테이프 보존

비교 기준은 `fix/mission-manager-handoffs`의 `9594ab5`다. 변경 대상은 공용 `stop_line_detector.py`의 영상 후보 판정과 회귀 테스트뿐이다. 출구 인계, 콘 내부 주행, 주차 시퀀스, 매니저, 속도·마진, 정지선 카운트, 거리 보정표와 odom 사각지대 추적 코드는 변경하지 않았다. 정지선 관측 결과가 달라지면 기존 소비 노드가 받는 입력은 달라진다.

## 왜 폭·면적 조건을 통과했나

`bag_full_d932049_20261117_010438`의 109.234초 원본 프레임에서 마름모의 오른쪽·하단이 잘린 영역은 640×480 영상 기준 bbox `(368,380,272,100)`이었다. 폭 272px은 기존 최소 폭 268.8px(42%)을 넘었고, 윤곽 면적 14,883.5px²도 ROI 면적의 약 11.5%로 최소 1.8%를 넘었다. 기존 가로 열림 처리와 폭·면적 조건만으로는 이 넓은 표식을 긴 테이프와 구분하지 못했다.

같은 프레임은 밝기 145에서 검출되지만 170·180에서는 검출되지 않았다. 그러나 밝기를 다시 올리면 어두운 실제 테이프도 놓친다. 이번 수정은 현재 YAML의 밝기 145와 기존 색상·폭·면적 기준을 유지한다. `StopLineConfig` 자체의 기본값 180도 변경하지 않았다.

한 프레임의 가짜 관측은 약 0.257m 정지선으로 odom 추적 기준점을 만들었다. 이후 영상에서 마름모가 사라져도 기존 추적기가 그 거리를 유지했고, 실제 횡단보도 시작선은 더 먼 선으로 취급되었다. 추적기의 안전 유지 기능을 제거하는 대신 잘못된 최초 관측을 막는다.

## 판정 변경

1. 기존 후보의 회전 최소사각형으로 길이와 **선에 수직인 두께**를 측정한다. 축에 평행한 bbox 높이를 두께로 쓰지 않으므로 비스듬한 테이프의 높은 bbox를 그대로 탈락시키지 않는다.
2. 길이/두께 ≥ 4.5, 두께 ≤ 전체 영상 높이의 15%, 수평 대비 각도 ≤ 35°, 윤곽 면적/회전사각형 면적 ≥ 35%를 요구한다. 실제 기록의 가까운 테이프 두께가 48px을 넘으므로 두께 상한을 높이의 10%로 좁히지 않았다. 480p에서는 상한 72px이다. 면적 충실도는 구겨진 테이프도 허용하도록 완전한 직사각형을 요구하지 않는다.
3. 가로 열림 처리에서 유효 후보를 찾지 못했을 때만 **원래 색상 마스크의 연결된 얇은 띠**를 보조 탐색한다. 동일한 폭·면적·형상 조건과 화면 중앙 45~55% 구간을 가로지르는 조건을 적용한다. ROI 위·아래에 잘린 후보는 이 보조 경로에서 제외한다. 흩어진 글자나 짧은 획들을 연결해 선을 만들지 않는다.
4. 기존 가로 후보가 유효하면 그 후보의 하단 행과 거리 계산을 그대로 쓴다. 보조 탐색으로 복원한 후보에만 원본 띠의 하단을 사용한다. 하단에 잘린 실제 수평 테이프는 기존 경로에서 계속 검출한다.

다중 프레임 대기, 신규 상태 유지, GPU 추론, 추가 의존성을 넣지 않았다. 35도를 넘는 매우 비스듬한 선, 크게 가려져 중앙을 가로지르지 못하는 선까지 보장하는 수정은 아니다.

## 원본 bag 전후 비교

외부 검증 도구 `m8_offline/verify_stop_line_shape.py`는 `git show 9594ab5`의 검출기와 수정 검출기에 동일한 원본 카메라 프레임을 넣는다. 양쪽 모두 현재 YAML의 밝기 145, 같은 거리 보정표, 각각 독립적인 기존 odom 추적기를 사용한다. 녹화 당시 실행 인자 전체는 기록되지 않아 런타임 덮어쓰기까지 재현한 것은 아니다.

- 새 bag의 133.55초 이전 구간에서 기존 검출 486프레임 중 제거된 것은 109.234초 마름모 1프레임뿐이다. 나머지 485프레임은 유지되었고 공통 검출의 하단 행도 동일하다.
- 새 bag의 다른 제거 172프레임은 이후 차로 이탈·수동 개입 구간의 밝은 바닥 패치다. 그 구간의 모든 바닥 반사 오검출이 사라진 것은 아니며, 이를 정상 주행 정지선 검증으로 계산하지 않는다.
- 109.234초 가짜 시각 관측과 그 관측에서 시작되던 odom 추적이 함께 사라진다. 111.305초 실제 횡단보도 정지선은 새 결과에서 약 0.556m로 잡힌다. 같은 시각 이전 결과는 가짜 선의 odom 잔여거리 약 0.060m였다.
- 이전 두 bag의 기존 검출 671프레임은 모두 유지되고, 공통 검출의 하단 행도 바뀌지 않았다. 새로 검출된 61프레임은 비교 이미지에서 비스듬하거나 구겨진 실제 흰 테이프임을 확인했다.
- `214231`의 비스듬한 선은 최초 검출이 38.128초에서 36.688초로 앞당겨졌다. 이것은 고정된 기록에서의 관측 개선이며 차량이 실제로 더 일찍 멈추거나 인계했다는 뜻은 아니다.

검출 함수 p95는 개발 Mac에서 bag별 약 2.19~2.38ms에서 2.35~2.55ms가 되었다. 이미지 디코딩·ROS 통신·전체 노드 비용은 제외하며 Jetson 성능 수치가 아니다.

## 테스트와 비교 영상

전체 Python 테스트 382개 통과. 신규 33개 사례는 밝기 150/160/170와 ±30도 테이프, 구겨진 어두운 테이프, 내부가 빈/찬 마름모와 잘린 마름모, 가까운 가짜 표식과 먼 실제 선의 동시 존재, 급경사 세로선, 바닥 패치, 분리된 짧은 획, 하단 실제 선, 거짓 odom 추적 시작 방지를 다룬다. 기존 M8 출구·미션 전환·주차 테스트도 유지했다.

검증 스크립트와 영상은 차량 저장소 밖 작업공간에 보관한다. 재사용 방법:

```bash
python m8_offline/verify_stop_line_shape.py BAG_DIR --repo VEHICLE_REPO \
  --out OUTPUT_DIR --ref 9594ab5 --video-window 103 127
```

스크립트는 원본 bag을 읽기 전용으로 열며 `comparison.csv`, `summary.json`, 차이 프레임 이미지와 비교 MP4를 만든다. 모든 프레임을 계산하고 영상 구간만 선택한다. `--video-window`는 여러 번 지정할 수 있다. 출력 위치는 `outputs/stop_line_shape_20261117/{new_compare,prior_compare,dark_compare}`다. 새 bag 영상은 103~127초, 이전 정상 bag은 64~100초, 어두운/비스듬한 선 bag은 12~18·36~40·49~60초다. 한 프레임짜리 마름모 제거를 눈으로 확인하도록 해당 프레임에서 1.5초 정지 화면임을 명시했다.

영상의 `/cmd_vel`, 미션 상태와 odom은 모두 **원래 기록값**이다. 새 검출로 차량을 움직이는 폐루프 시뮬레이션은 아니다. 미션 카운트 정상화, 정지 위치, 주차 성공 여부는 다음 실차 주행에서 확인해야 한다.

## 실차 확인 항목

1. 마름모 위를 지날 때 정지선 검출·거리 기준점이 생성되지 않는지 확인한다.
2. 어두운 실제 정지선과 우회전 직후 비스듬한 선이 계속 잡히는지 확인한다.
3. 서행 시작선 → 횡단보도 시작선 → 횡단보도 끝선 → 주차 시작선의 관측과 기존 매니저 전환이 일치하는지 확인한다.
4. 실제 테이프가 연결된 글자·반사광과 합쳐지거나 35도 이상 기울어지는 새로운 장면은 원본 카메라와 정지선 거리/검출/행 비율 토픽으로 추가 확인한다.
