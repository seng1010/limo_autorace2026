# M8 출구 차선 역할 확인과 콘 명령 유지

브랜치 `fix/mission-manager-handoffs`. 최초 역할 보정은 `3673684` 대비 `bag_full_20261116_234026`으로 확인했고, 아래 연속 추적·명령 인계 보완은 `d932049` 대비 `bag_full_d932049_20261117_010438` 및 같은 이전 기록으로 확인했다.

## 원인과 수정 범위

콘 출구에서 차량이 아직 차로 오른쪽 밖에 있을 때 실제 오른쪽 노란선이 화면 왼쪽에 보였다. 기존 차선 노드는 이를 왼쪽 경계로 이어 붙였고, 선의 오른쪽에 중심 경로를 만들었다. LiDAR 충돌검사만으로는 이 경로가 차로 밖이라는 사실을 구분할 수 없다.

일반 `LaneEngine`, 주차 시퀀스, 속도, 충돌검사와 마진은 변경하지 않았다. `simple_lane`의 수정은 이미 처리한 영상·odom 자세·좌표 변환을 M8 관측기에 넘기는 호출부뿐이다. 두 번째 차선 처리 파이프라인을 실행하거나 일반 차선 결과를 덮어쓰지 않는다.

## 경계 역할을 확인하는 방법

`m8_exit_lane.ExitLaneResolver`는 현재 노란선과 횡방향 흰 정지선의 접점을 검사한다. 흰 선이 노란선 왼쪽으로 이어지면 오른쪽 경계, 오른쪽으로 이어지면 왼쪽 경계로 판단한다. 화면 절반, 첫 검출 순서, 우회전 규칙만으로 역할을 정하지 않는다. 양쪽으로 가로지르는 흰 선, 세로 반사광, 상충하는 접점은 근거로 쓰지 않는다.

흰 테이프에서 청색 채널이 포화되어 HLS 포화도가 높게 나오는 기록을 반영해 이 전용 접점 관측에는 HSV 저채도 마스크를 사용한다. 공용 정지선 검출 기준은 그대로다.

현재 관측된 경계를 뒤 차축 좌표에서 odom 좌표로 옮겨 같은 경계인지 확인한다. 서로 다른 영상 3회와 공간 연결이 있어야 확정하며, 단 한 번의 접점을 예측으로 재사용해 확정하지 않는다. 두 경계 각각 최대 40개 점만 저장한다. 정지선 접점은 최초 좌우 역할을 정하고, 이후에는 250ms 이내의 실제 노란선 관측이 odom 공간에서 기존 경계와 계속 일치하면 그 역할을 유지한다. 최초 접점으로부터 4초·1m가 지났다는 이유만으로 현재 관측을 폐기하지 않는다. 250ms 넘게 대응 관측이 없으면 역할 추적을 끊고, odom 유실·불연속·점프·후진은 초기화한다. 현재 노란선이 없으면 기억만으로 경로를 허용하지 않는다.

확정한 경계에서 차로 안쪽으로 반폭을 띄운 M8 전용 경로를 만든다. 기존 차선 노드가 계산한 폭이 42~62cm 안이면 사용하고, 그렇지 않으면 기존 기준폭 52cm를 사용한다. 이는 차체 충돌 여유를 줄이는 설정이 아니다. 두 경계의 중심 후보가 불일치하거나 오프셋 곡선이 접히면 해당 부분을 경로로 연결하지 않는다.

## 명령 선택과 다음 미션

- 출구선 확인은 기존대로 출구 준비만 시작한다.
- 기존 차선 경로와 검증된 출구 경로가 다르면, **최신 유효 콘 명령을 우선 유지**한다. 과거 조향을 고정하는 기능이 아니다.
- 콘 명령이 없으면 역할을 확인한 출구 경로를 기존 40cm LiDAR 연결 원호 검사에 넣는다. 통과한 명령만 사용한다. 콘·출구 명령이 모두 없으면 기존 제한 복구 또는 정지한다.
- 기존 차선 경로와 검증 경로의 겹치는 구간 오차 90분위가 8cm 이하로 3프레임 이어지고, 기존 명령이 TRACK이며 조향 제안 차이가 10도 이하이면 일반 차선으로 넘길 준비가 된 것으로 본다.
- 위 일치가 확인되면 **현재 차선 명령을 지우지 않고 기존 `checked_exit_lane` 검사로 전달**한다. 동일 카메라 시각의 역할·일치 근거와 최신 LiDAR가 필요하며, 기존 30cm 차체 이동 구간 충돌검사 및 관측 범위를 통과해야 0.10m/s로 전달한다. 불일치하면 현재 콘 명령을 유지하거나 기존 40cm 연결 원호를 사용한다. 먼 관측점에 40cm 원호 끝이 닿지 못한다는 이유로, 이미 정렬된 안전한 차선 명령까지 버리지 않는다.
- M8 종료에는 위 일치 확인과 기존 출구 통과·odom 진행 조건이 모두 필요하다. 잘못된 일반 차선 결과로 M1에 넘겨 같은 오인을 반복하지 않는다.
- 출구 제안이 다시 끊겨도 최신 충돌검사를 통과한 콘 명령이 남아 있으면 이를 사용한다. 명령 만료 250ms, ESTOP, odom 검사는 유지한다.

`/mission/cone/exit_lane_evidence`는 `PointStamped`다. stamp는 카메라 원본 시각, frame은 `rear_axle`, x는 역할을 확인한 현재 경로(1/0), y는 일반 차선과 인계 가능한 일치(1/0), z는 예약값 0이다. 출구 검사는 동일 카메라 시각의 경로·힌트·근거만 결합한다. 일반 M2 접근에는 이 조건을 적용하지 않는다.

## 최초 역할 보정의 기록 재생 결과

외부 도구 `m8_offline/verify_exit_boundary.py`는 원본 카메라 1,104프레임과 CameraInfo를 사용한다. 차선은 기본 튜닝값으로 순차 재계산하고, 실제 `MissionConeAvoidNode._publish_exit` 및 `M8Control` 메서드를 가짜 ROS 통신으로 실행한다. 콘 명령·센서 위치는 기록값을 유지한다. 수신 순서와 처리 지연은 재생 근사이며 실차 DDS 재현은 아니다.

| 확인 대상 | 결과 |
| --- | --- |
| 39.6~44.6초 노란선 역할 | 150프레임 모두 오른쪽 경계, 일반 차선과 불일치 확인 |
| 같은 5초의 50ms 명령 표본 | 이전 우조향 90/100, 수정 후 우조향 0/100 |
| 수정 후 선택 명령 | 100/100 기존 유효 콘 명령, 속도 0.10m/s |
| 전체 출구 후보 충돌검사 | 이동 허용 후보 66개, 받침 보정 후 최소 계산 여유 약 3.74cm; 요구 여유 2cm 유지 |
| 추가 역할 관측 계산 | 개발 Mac p95 약 2.9ms; Jetson 실측 아님 |

이후 이미 바깥으로 벗어난 고정 위치에서는 노란선과 콘을 모두 놓쳐 정지 표본이 남는다. 새 조향으로 움직였다면 이후 센서 위치가 달라지므로, 이 재생 결과는 완주나 충돌 없는 실차 주행의 증명이 아니다. 영상의 초록 선은 출구 후보 경로, 아래 노란 원호가 실제 선택 명령의 예상 원호다.

## 연속 관측과 명령 인계 보완

`d932049`에서 새 기록의 정지 원인은 두 부분이었다. 최초 접점 이후 4초가 지나면 현재 관측 중인 경계의 역할까지 지웠다. 그 전에도 차선이 출구 경로와 일치하는데 명령을 무조건 0으로 만들고, 짧은 연결 원호만 시도했다. 약 62초부터는 관측 중심점의 앞방향 거리가 길어져 원호의 끝과 경로 사이 거리 조건에서 탈락했다. 이 탈락은 3.5cm 마진 부족과 다른 원인이다.

이번 수정은 역할 추적의 수명을 최신 대응 관측 기준으로 바꾸고, 일치한 차선 명령에 이미 구현된 직접 충돌검사 경로를 연결한다. 받침 보정 1.5cm와 추가 여유 2cm, 콘 내부 경로 계산, 일반 차선 계산, M8 종료를 위한 출구 통과·odom 조건, 주차, 정지선 검출과 카운트는 바꾸지 않았다. 출구 수신 노드도 evidence.y=1을 재확인하여 불일치한 일반 차선 명령을 직접 사용하지 않는다.

외부 검증 도구 `m8_offline/verify_exit_handoff.py`는 Git의 `d932049` 모듈과 작업 버전의 실제 관측기·출구 검사 메서드를 같은 카메라/CameraInfo/scan/odom 입력으로 실행한다. 기존 콘 명령을 유지하고 실제 `M8Control`로 최종 선택까지 비교한다. 이 도구와 MP4는 차량 저장소 밖 검증 작업공간에 보관한다.

| 대상 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 새 기록 63~70초, 출구 검사 70회 중 이동 허용 | 0회 | 70회, 모두 0.10m/s |
| 같은 구간 매니저 50ms 표본 140회 중 이동 명령 | 0회 | 140회, 검증된 차선 선택 |
| 이전 기록 39.6~44.6초, 차로 밖 우조향 명령 | 0/100회 | 0/100회, 유효 콘 명령 유지 |
| 검사 통과 원호의 받침 보정 후 최소 여유, 새/이전 기록 | 약 3.67/3.74cm | 약 4.16/3.74cm |

최소 여유 수치는 근거리 반환점이 있는 허용 원호의 기존 30cm 검사 구간 기준이다. 요구 추가 여유 2cm는 그대로다. 근거리 반환점이 없는 열린 공간은 기존 연결 원호의 유한 LiDAR 빔 관측 조건을 유지하며, 반환점 없음에 임의의 최소 거리를 부여하지 않는다.

새 기록에는 exit_line·실시간 차선 튜닝·처리 지연 토픽이 없으므로 출구선은 기존 검출기와 보정표로 재계산하고, 차선은 기본 튜닝, 통신 순서는 기록 수신 시각으로 근사한다. 영상은 새 기록 54~72초와 이전 기록 35~49초를 비교한다. 카메라 위 경로와 별도로 아래 노란 원호는 **매니저가 선택한 명령**이며, 기록 odom 속도는 수정 후 예측 속도가 아니다.

고정 기록에서 차량은 63초 이후 멈춰 있으므로 새 명령을 실제로 실행했을 때의 추가 이동과 M1 인계 완료는 재현할 수 없다. 이를 성공률로 표현하지 않는다. 별도 합성 연결 테스트는 현재 차선 관측 → 실제 충돌검사 → 매니저 → odom 출구 통과 → M1까지 실행하며, 정지 중에는 조기 종료하지 않는지도 검사한다.

전체 테스트 349개 통과. 연속 관측 4초·1m 초과 유지, 관측 유실·다른 선·후진·역할 충돌·중복 경계 방어, 3.4cm 여유 거부/3.6cm 허용, 명령 만료, 불일치한 차선 명령 차단, M1 인계 조건을 포함한다. 실차 CPU 시간·실제 출구 완주 여부는 다음 주행에서 확인한다. 마름모 등 가짜 정지선 문제는 이번 수정 대상이 아니다.

## 실차 확인

1. 출구에서 실제 오른쪽 선이 화면 왼쪽에 보여도 M8 출구 후보는 선의 안쪽에 생기는지 확인한다.
2. evidence.x=1, y=0인 동안 유효한 콘 명령이 유지되는지 확인한다.
3. 콘 제안이 사라질 때 역할 검증·LiDAR 검사를 통과한 연결 명령만 사용되는지 확인한다.
4. 차로로 정렬되어 evidence.y=1이 된 뒤 기존 통과 조건으로 M1에 넘어가는지 확인한다. 일반 차선 재포착 지연은 실차 확인이 필요하다.
5. 기록에는 새 evidence 토픽과 기존 observed_center, geometry_hint, safe_cmd_vel, safe_exit_cmd_vel, control_timing을 함께 넣는다. `m8_cone.launch.py record:=true`에는 새 토픽을 추가했다.

기존 고정 bag 녹화 명령을 사용한다면 토픽 목록에 `/mission/cone/exit_lane_evidence`를 추가한다. 자동 후진, 속도 증대, 가벽 대응, 주차 위치 변경은 이 커밋의 범위가 아니다.
