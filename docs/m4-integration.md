# M4 코드 통합 범위

M4 `fc6470c`를 main `d142030`에 통합한 뒤, `fix/mission-manager-handoffs`에서 매니저 연결을 추가했다.
팀원이 튜닝하는 주차 단계의 시간·속도·조향값은 변경하지 않았다.

- `jetracer_ros2/mission_parking_node.py`: 기존 파일은 수정 없이 보존하지만, 이 브랜치의 매니저는 더 이상 이 노드를 M4에 자동 실행하지 않는다.
- `jetracer_ros2/parking_timed_test_node.py`: M4 브랜치의 `mission_parking_node.py`를 내용 변경 없이 별도 이름으로 보존했다. 직진/회전/진입 시간 1.7/1.8/0.1초, 직진·회전 속도 0.50m/s의 시험 버전이다.
- `jetracer_ros2/parking_test_node.py`: M4 원본 파일을 유지한다. 시간 1.5/2.5/1.5초, 속도 0.10/0.08m/s의 별도 시험 버전이다.
- `jetracer_ros2/parking_line_detection.py`: 단독 실행은 기존 접근·주차 동작을 보존한다. 새 `parking_line_detection_managed` 실행 항목은 같은 파일·튜닝값을 사용하되, 접근은 매니저에 맡기고 시작 신호 이후 `STOP_WAIT`부터 실행한다.
- `mission_parking_avoid_node.py`: 패키지 디렉터리 바깥의 빈칸 탐색·회피 시험 코드 위치를 유지한다.

단독 시험 노드들은 기본적으로 `/cmd_vel`에 직접 출력한다. 전체 주행 매니저와 동시에 실행하지 않는다.
새 **managed 실행 항목만** `mission/parking/cmd_vel`로 제안하고, 매니저가 최종 `/cmd_vel`을 발행한다.
`setup.py`에 실행 항목을 등록했으므로 LIMO에서 패키지를 다시 빌드해야 한다.

## 주차 인계 순서

1. M1 완료 후 M4에 진입하면 매니저는 주차 노드를 대기 상태로 실행하고 **차선 명령**을 계속 선택한다. 이전 M1 정지선과 이전 주차 명령의 수신 기록은 폐기한다.
2. M4에서 새 정지선 거리가 `m4_line_arm_distance_m` 이내가 되면 접근 상태가 된다. 횡단보도 M3와 동일한 `StopApproachController`로 속도를 제한한다. 속도와 각속도를 같은 비율로 줄여 차선 명령의 조향 곡률을 유지한다. 임의로 조향을 0으로 만들지 않는다.
3. 앞바퀴 축 기준 거리 `m4_stop_offset_m`에 도달하면 정지 명령을 유지한다. 신선한 odom의 속도가 `full_stop_speed` 이하로 `full_stop_sec` 동안 유지되어야 시작 신호를 보낸다. 명령 속도 0만으로 정지를 확정하지 않는다.
4. 주차 노드는 자체 직진 접근을 건너뛰고 기존 `settle_sec` 대기 → `forward` → `turn` → `enter`를 실행한다. 이 단계들의 파라미터와 아커만 변환식은 그대로다.
5. 주차 `DONE`은 `mission/parking/state=complete`로 매니저에 전달한다. 매니저는 최종 M4를 유지하고 정지한다. 표지판을 먼저/늦게 보는 것이 주차 시퀀스를 직접 시작하거나 재시작하지 않는다.

사용자가 지정한 시작 자세는 **차로 좌우 중앙 부근, 앞바퀴 축이 정지선 가까운 가장자리 부근**이다. 좌우 중앙 접근은 기존 차선 주행에 맡긴다. 매니저가 실제 중앙 정렬이나 바퀴 조향각을 측정·확정하는 것은 아니다.

| 설정 | 초기값 | 의미 |
|---|---:|---|
| `m4_line_arm_distance_m` | 0.80 m | M4 정지선 접근 판단 시작 |
| `approach_start_m` | 0.50 m | M3와 공유하는 감속 시작 거리 |
| `m4_stop_offset_m` | 0.01 m | 정지 명령을 내기 시작할 앞바퀴 기준 남은 거리 |
| `full_stop_speed` | 0.01 m/s | 실측 정지 판단 기준 |
| `full_stop_sec` | 0.3 s | 정지 확인 지속 시간 |

0.01 m는 M3 공용 정지 보정값과 같은 초기값이지 실측 보장값이 아니다. 정지선 검출 보정, 제동거리, 낮은 속도에서의 실제 구동 여부를 LIMO에서 확인해야 한다. 접근 최저속도 `approach_creep_speed=0.06`은 이번에 바꾸지 않았다. 이 값에서 실차가 움직이지 않는다면 정지선 전에 대기할 수 있으므로 정지선 정확도와 함께 별도 튜닝한다.

## 명령 소유권과 중단

- M4 접근·정지 확인: 매니저가 차선 제안을 선택한다.
- 주차 시퀀스: 매니저가 주차 제안을 선택한다. 차선·3차선·콘 검출/경로 생성 코드는 수정하지 않았다.
- 시작 허가는 20 Hz로 반복 발행한다. 노드가 늦게 실행되어도 단발 시작 신호를 놓치지 않는다.
- managed 주차는 시작 허가가 0.5초 넘게 끊기거나, 현재 미션 알림이 M4가 아니거나 1.5초 넘게 끊기면 정지하고 타이머 진행을 일시 중단한다. 새 허가 시 남은 단계 시간을 이어간다.
- `ESTOP`은 미션별 정지와 별도로 유지하며 `NEXT`, 완료 이벤트, M8 즉시 발행 콜백으로 해제되지 않는다. `ESTOP_CLEAR` 후에는 이전 명령을 버리고 새 제안을 기다린다. 주차 단계 자체를 처음부터 재시작하지 않는다.
- 기존 단독 `parking_line_detection.py` 실행의 `go`/Enter, `start_delay_sec`, 자체 접근 방식은 유지한다. managed 실행에서는 접근/시작 권한을 매니저가 소유한다.

## 같은 브랜치의 매니저 수정

- 신호등 상태 수신이 `traffic_state_timeout_sec=0.5`초 넘게 끊기면 마지막 녹색을 새 출발 판단에 재사용하지 않는다. 이미 교차로를 통과 중인 M1의 기존 상태 판단은 바꾸지 않았다.
- `m1_max_wait_sec=0`으로 기본값을 변경했다. 적색/미확인 상태에서 30초만 지나 자동 출발하던 우회는 기본 비활성이다. 양수로 명시하면 기존 우회가 재활성화된다.
- M1/M3에서 odom이 없거나 만료되면 명령값으로 완전정지를 추정하지 않고 대기한다. 관측 공백 뒤 정지 확인 시간을 새로 센다.
- M1/M3 완료 직후 같은 타이머 실행에서 이전 명령이 전환 정지 명령을 덮어쓰지 않는다.
- 전체 주행의 매니저 설정에 M8 단독 launch와 동일한 입구 설정(55 cm 사전검사, 45 cm 보호접근)을 연결했다. M2 진입 즉시 콘 제어를 선택하는 것은 아니며, 콘 내부·충돌검사·출구 조건은 그대로다.

## 검증과 남은 연결

`test/test_mission_manager_transitions.py`는 실제 매니저와 주차 노드의 콜백을 가짜 ROS 통신·시각으로 실행한다. 하드웨어로 명령을 전송하지 않는다.

- 미션 순서, 비상정지와 완료 이벤트 경합, M8 즉시 발행 경로, 신호등 만료/적색 대기, odom 유실을 확인한다.
- M2 차선 유지 → M8 사전검사·인계, 실제 M8 출구 판정 → M1 노드 시작, M1 완료 → M4 차선 접근을 확인한다.
- 매니저/주차 노드를 연결해 정지 확인 → 허가 → 기존 시퀀스 → 완료 통지를 검사한다. 단독 시험 동작과 튜닝값 보존도 확인한다.
- `test_curve_approach_through_m8_traffic_light_and_final_parking`은 M8 직전 곡선의 차선 명령 → 55/45cm 접근 → 콘/출구 인계 → M1 적색 정지·녹색 출발 → M4 정지·주차 완료를 한 매니저 인스턴스로 연속 실행한다. 이 테스트는 강제 DONE 이벤트나 내부 상태 덮어쓰기 없이 거리·odom·검사된 제안·신호 색 입력을 제공한다. 차선/콘 검출 자체와 차량 물리는 모사하지 않는다.
- **M7 완료 이벤트의 생산자는 아직 없다.** 순서 테스트의 `M7_DONE`은 외부 이벤트를 명시적으로 넣은 것이며, 현행 3차선 노드가 자동으로 발행한다고 주장하지 않는다. 이를 해결하려면 차선/3차선 쪽에 종료 이유를 구분한 완료 알림 연결이 필요하다. 사용자 승인 전에는 수정하지 않았다.
- M1의 `m1_skip_lines=1`, M3/M1의 거리 초과 시 건너뛰기, section 노드의 정지선 확인 방식은 이번에 변경하지 않았다. 트랙 배치 및 규정 적합성은 별도 확인 대상이다.
- 테스트 통과는 **ROS2 실차 구동·전체 코스 완주·주차 위치 정확도 검증이 아니다.** 특히 M7 종료 연결이 없어 전체 자동 전환이 완성된 상태는 아니다.

실차 확인 순서: M4 접근만 확인(정지선 거리·차선 조향·odom 정지 시점) → 주차 시퀀스 시작 자세/타이밍 확인 → 정차 중 ESTOP/해제 확인 → M8→M1→M4 연속 인계 확인. 기존 단독 주차 노드와 managed 주차를 함께 실행하지 않는다.

이번 사용자의 실차 시험 범위는 **M8 직전 곡선부터 최종 주차 정지까지**다. 하드웨어 launch는 한 번만 실행하고, 재빌드 후 `ros2 launch jetracer_ros2 all_in_node.launch.py start:=M2`로 전체 매니저 스택을 시작한다. 이때 M2는 해당 시험의 접근 시작 상태이며 M7을 실행하지 않는다. `m8_cone.launch.py`는 콘 단독 시험에서 `auto_start_mission_nodes=false`를 사용하므로, 신호등과 주차까지 자동 실행하는 이번 연속 시험 명령으로 사용하지 않는다.

M4 브랜치에 함께 들어 있던 M5 시험 파일도 그대로 보존했지만 기존 서행 로직에 연결하지 않았다. 별도 M5 브랜치와 통합할 때 `m5-runner-node.py` 중복 및 판단 모듈 API를 정리해야 한다.
